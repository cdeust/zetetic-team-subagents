# Plan: one CI pipeline run by the Claude bot

Implements `docs/superpowers/specs/2026-10-22-single-ci-design.md`
(decisions 1 to 9 included). Each task is one commit, test-first, in a
worktree under `<repo>/.claude/worktrees/`; every PR is left to the Claude
bot once pushed.

## Phase 1: the template and its renderer (zetetic-team-subagents)

### Task 1.1: `ci.json` contract validator

- `tools/ci_contract.py`: reads `ci.json` at the repo root; exits 1 with one
  line per fault when a key is missing, empty or not a string; keys are
  exactly `unit`, `regression`, `e2e`, `environment`, `install`; optional
  `version_file` (default `.claude-plugin/plugin.json`, decision 9) must
  exist. Prints the five commands when valid.
- Tests `tests/test_ci_contract.py`: missing file, missing key, empty
  command, extra key, valid file, version file absent. Fail-before: the
  module does not exist.

### Task 1.2: coverage reader

- `tools/ci_coverage.py <coverage.xml> --min 90`: parses Cobertura
  `line-rate`, exits 1 under the threshold, prints the percentage.
- Tests: file absent, malformed XML, 89.9 %, 90.0 %, 100 %.

### Task 1.3: the `ci.yml` template

- `templates/ci/ci.yml` (new directory; `scripts/setup.sh` gets a
  `render-ci <target-repo>` subcommand that copies the template to
  `<target>/.github/workflows/ci.yml` with a header line
  `# generated by zetetic-team-subagents render-ci <template-sha>`).
- Jobs, exactly as the design's section "ci.yml, generated from one
  template": `contract`, `unit` (reads `coverage.xml` through
  `tools/ci_coverage.py` vendored into the template as an inline Python
  step, so the target repo needs no copy), `regression`, `e2e`,
  `environment` (matrix ubuntu/macos/windows, pinned Claude Code CLI),
  `install` (same matrix, fresh `HOME`/`CLAUDE_CONFIG_DIR`), `review`,
  `merge`, `tag`.
- `review`: two `anthropics/claude-code-action@a5a423f` steps, the
  documented `code-review` plugin invocation with `--comment`, then the fix
  step with the failed-job log URLs in its prompt (design "The bot step").
  Guard keyed on the head SHA (decision 8): skip when the head commit author
  is the bot, when the PR is a draft, when the head repo is a fork, and when
  the diff touches `.github/workflows/ci.yml` (decision 2). `allowed_bots:
  "dependabot[bot]"` is NOT set: Dependabot is out of scope (decision 5), so
  `review` skips when `github.actor == 'dependabot[bot]'`.
- `merge`: `if: always() && needs.review.result != 'failure' && <jobs 2-6
  all success>` (decision 4). Checkout with
  `ssh-key: ${{ secrets.RELEASE_TAG_SSH_KEY }}`; runs `gh pr merge --auto
  --squash` with `GH_TOKEN` = the workflow token (arming auto-merge triggers
  nothing; the merge itself is done by GitHub).
- `tag` (push to main): Cortex's release-gate block verbatim
  (ci.yml:1175-1280 of Cortex at 2026-10-22): guard on the secret, checkout
  over the deploy key, read the version from `version_file`, tag
  `vX.Y.Z` when absent, push the tag over SSH so the release workflows
  fire (decision 1).
- `actionlint` on the template is a test in `tools/tests/ci-template/`.
- Pinned CLI version: `@anthropic-ai/claude-code@2.1.296` (Cortex's
  measured pin), installed with `npm install -g` on the three OS.

### Task 1.4: `render-ci` and its test

- `scripts/setup.sh render-ci <path>` writes the file and `ci.json` from
  an example when absent; idempotent (second run changes nothing).
- Shell test under `tools/tests/render-ci/run-tests.sh`: renders into a
  temp git repo, diff against the template, header line present,
  idempotence.

### Task 1.5: zetetic-team-subagents' own `ci.json` and bootstrap

- `ci.json` for this repository: unit = `python -m coverage run -m pytest
  -q && python -m coverage xml`; regression = `bash tests/run-all.sh`;
  e2e = the `scripts/test-memory-*.sh` suites; environment =
  `bash scripts/setup.sh install --dry-run` followed by
  `tools/plugin-version-check.sh --json` (setup.sh has no `check`
  subcommand; its Verification step runs inside `install`, setup.sh:353-430);
  install =
  `claude plugin install zetetic-team-subagents@zetetic-marketplace` into a
  fresh `CLAUDE_CONFIG_DIR` then `claude --init-only`.
- Raise `fail_under` to 90 in `pyproject.toml` (red until coverage is
  there; the bot sees it).
- Delete the PR-triggered workflows the design retires: codeql.yml,
  identity.yml, shellcheck.yml, scorecard.yml's `pull_request` trigger;
  keep release.yml (tags).
- Replace `.github/workflows/ci.yml` with the rendered one. This PR gets
  no bot review (decision 2); it merges on green tests.

## Phase 2: the seven other repositories, one PR each

For each: new worktree from `origin/main`, `render-ci`, write `ci.json`
from the inventory, remove the retired PR workflows, keep tag-triggered
releases, push, open the PR, stop. Order: smallest first so the template
is exercised early.

| Repo | unit | regression | e2e | environment | install |
|---|---|---|---|---|---|
| claude-mods | `claude plugin validate` + `claude plugin test` per mod, with coverage from `node --test --experimental-test-coverage` emitting Cobertura | `sh scripts/check-shared.sh` | to write (no e2e today) | load each mod with `claude --plugin-dir` and run one hook | `/plugin install <mod> --marketplace <checkout>` in a fresh config dir |
| cortex-know-when-to-stop-training-model | `pytest --cov --cov-report=xml` | `python scripts/validate_data.py` | to write | `python -c "import cortex_beam_abstain"` after `pip install .` | `pip install .` in a fresh venv on the three OS |
| session-optimizer | `coverage run -m pytest -q && coverage xml` | `tests/statusline/*.sh` | to write | `plugins/statusline/install.sh verify` | `/plugin install context-guard\|refine-gate\|statusline@session-optimizer-marketplace` from the checkout |
| cortex-viz | `uv run coverage run -m pytest && coverage xml` + `vitest --coverage` merged | `npm test` | to write | launcher starts and the Trace view answers (no PostgreSQL) | `claude plugin install hypermnesia-mcp-viz` from the checkout's marketplace |
| ai-architect-mcp-spec | `pnpm test:coverage` (Cobertura reporter) | `pnpm test:perf` | `pnpm run test:portable` | `check_health` over stdio after `bash bin/ensure-deps.sh` | `claude plugin install ai-architect-mcp-spec@...` from the checkout |
| ai-architect-mcp-codebase | `cargo llvm-cov --cobertura` | `cargo test --test graph_accuracy` | `python3 scripts/smoke_claude_plugin.py` | `ai-architect-mcp-codebase install --dry-run` | `claude plugin install ...` from the checkout (red on Windows until the plugin supports it) |
| Cortex | the test-suite action's pytest with `--cov-report=xml`, SQLite backend | `pytest tests_py/integration` on SQLite | `scripts/docker_smoke.sh --skip-build` | `cortex-doctor` after install | `scripts/install_e2e/run.py` on the three OS (Windows leg new) |

"To write" cells are red on day one by design; the PR carries a failing
`ci.json` entry that names the missing test, and the bot reports it.

## Phase 3: what the pipeline cannot do (done 2026-10-22)

- Deploy keys + `RELEASE_TAG_SSH_KEY` on the seven repos: done.
- Branch protection `merge`-only on the eight: done.
- Claude GitHub App on ai-architect-mcp-codebase: verify at its bootstrap
  (`gh api repos/cdeust/ai-architect-mcp-codebase/installation` is not

## Acceptance

- Phase 1 PR green on this repository's own rendered `ci.yml`.
- One real PR on zetetic-team-subagents after bootstrap: the bot reviews,
  pushes a fix, the five jobs re-run on its commit, `merge` arms
  auto-merge, GitHub merges, `tag` runs on main and the release workflow
  fires from the tag. Every step observed in the Actions log, cited in
  `docs/verification/`.
